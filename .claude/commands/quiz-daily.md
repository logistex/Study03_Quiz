# 매일 문항 늘리기

`/quiz-add`로 카테고리마다 문항을 하나씩 더하고, 이어서 `/quiz-validate`로 전체 문항을 점검한다.

**인수는 받지 않는다.** `$ARGUMENTS`에 값이 들어와도 무시한다.

두 단계의 절차는 각 명령어 파일에 있다. 이 파일은 그 파일들을 **다시 적지 않고 가리킨다.** 문항 작성 규칙, 출처 대조 방법, id 규칙, 문서 수치 갱신 표는 모두 하위 파일에 있는 것을 그대로 따른다.

## 순서

### 1단계: 문항 추가

`.claude/commands/quiz-add.md`의 1~9단계를 그대로 따른다. 개수 `n`은 **`1`로 본다**(카테고리마다 1개, 모두 4개).

그 파일의 다음 규칙이 여기서도 그대로 적용된다. 이 파일에서 바꾸거나 건너뛰지 않는다.

- 5단계 승인 전까지 어떤 파일도 고치지 않고, 승인을 기다리며 멈춘다.
- 7단계 점검이 하나라도 실패하면 되돌리고 커밋하지 않는다.
- 9단계에서 커밋까지만 하고 **master 병합과 푸시는 하지 않는다.**

### 2단계 진행 여부 확인

1단계가 커밋까지 끝났는지 확인한다.

```bash
git log --oneline -1
```

커밋까지 끝나지 않았으면 **2단계를 돌리지 않고 멈추고**, 무엇이 왜 막혔는지 보고한다. 되돌려진 `questions.js`를 점검해도 어제와 같은 결과만 나오기 때문이다. 멈추는 경우는 이런 것들이다.

- 사용자가 5단계 승인을 하지 않았다
- 7단계 점검이 실패해 되돌렸다
- 새 id가 99를 넘어 1단계에서 멈췄다
- 출처가 맞지 않거나 열리지 않아 주제를 다 버렸다

### 2단계: 전체 점검

`.claude/commands/quiz-validate.md`의 절차를 **인수 없이**(= 전체 문항) 따른다.

**점검 결과는 보고만 한다.** 새로 넣은 문항에서 규칙 위반이 나와도 문항을 고치거나 1단계 커밋을 되돌리지 않는다. quiz-validate의 읽기 전용 성격을 이 명령어에서도 깨지 않는다. 커밋은 브랜치에 있으니, 고칠지 되돌릴지는 사용자가 따로 지시한다.

## 보고

두 단계가 끝나면 다음을 한 번에 보고한다.

- 추가한 문항의 id와 주제
- 카테고리마다 몇 개가 되었고 전체가 몇 개인지
- 브랜치 이름과 커밋 해시
- 2단계 점검표 요약(어긋난 문항 수, 없으면 "없음"). 어긋난 문항이 있으면 quiz-validate의 표를 그대로 낸다
- 규칙 4(출처 2곳 이상)는 quiz-validate가 파일만으로 확인할 수 없다는 안내
- master 병합과 푸시는 하지 않았고, 사용자가 따로 지시하면 된다는 안내
