# 문항 추가

네 카테고리 모두에 `$ARGUMENTS`개씩 새 문항을 만들어, 사용자 승인을 받은 뒤 `questions.js`에 넣는다. 카테고리마다 문항 수가 같아야 하므로 항상 네 카테고리를 함께 늘린다.

| 카테고리 | id 접두어 |
|---|---|
| 한국사 | `kh` |
| 세계지리 | `wg` |
| 과학 | `sc` |
| 예술과 문화 | `ac` |

**5단계에서 사용자가 승인하기 전에는 어떤 파일도 고치지 않는다.** 4단계까지 만든 문항은 채팅으로만 보여 준다.

## 1. 인수 확인

`$ARGUMENTS`를 1 이상의 정수 `n`으로 읽는다. 비어 있거나 숫자가 아니거나 0 이하이면, 아무 일도 하지 말고 "카테고리당 몇 문항을 더할지 숫자로 알려 달라"고 되묻고 멈춘다.

만들 문항은 모두 `4 × n`개다.

## 2. 현재 상태 파악

1. `CLAUDE.md`의 규칙 10개, `PRD.md` 4.1~4.3, `IMPL-PLAN.md`의 "문항 작성 절차"를 읽어 기준을 확인한다.
2. 지금 문항 수와 마지막 번호를 뽑는다.

   ```bash
   node -e "const fs=require('fs'),vm=require('vm');const c=vm.createContext({});vm.runInContext(fs.readFileSync('questions.js','utf8')+';globalThis.Q=QUESTIONS;',c);const P={'한국사':'kh','세계지리':'wg','과학':'sc','예술과 문화':'ac'};for(const[cat,p]of Object.entries(P)){const ids=c.Q.filter(q=>q.category===cat).map(q=>q.id);const max=Math.max(0,...ids.map(i=>Number(i.slice(-2))));console.log(cat,'| 문항',ids.length,'| 마지막',max,'| 다음',p+'-'+String(max+1).padStart(2,'0'))}"
   ```

3. **네 카테고리의 문항 수가 서로 다르면 멈춘다.** 이미 어긋난 상태에서 더하면 균형을 맞출 수 없다. 현재 수를 알리고 사용자 지시를 기다린다.
4. 새 id는 카테고리마다 위에서 나온 "다음" 번호부터 `n`개를 이어 쓴다. 번호는 두 자리(`kh-11`)이고, 기존 번호를 재사용하지 않는다.
5. 기존 문항의 주제를 모두 읽어 둔다. 새 문항은 **기존 문항과 주제가 겹치지 않아야** 한다. 인물·사건·작품·지명이 같으면 겹친 것으로 본다.

## 3. 출처 확인 (문항마다)

난이도는 대학 1학년이 "들어 본 적은 있는" 수준으로 잡는다.

1. WebSearch로 사실을 찾고, **WebFetch로 그 사실이 적힌 페이지를 직접 연다.** 검색 결과 요약만 보고 쓰지 않는다.
2. CLAUDE.md 규칙 4에 따라 **서로 다른 기관 2곳**을 열어 같은 사실을 확인한다. 같은 기관의 다른 페이지는 2곳으로 치지 않는다.
3. **두 출처의 값이 다르면 그 사실은 버리고 다른 주제로 바꾼다.** 문제에도 해설에도 쓰지 않는다.
4. 페이지를 열 수 없거나 내용이 확인되지 않아도 그 주제를 버리고 바꾼다.
5. 쓸 출처: 국사편찬위원회 우리역사넷(contents.history.go.kr), 한국민족문화대백과사전(encykorea.aks.ac.kr), 국가유산청, 브리태니커(britannica.com), 유네스코 세계유산센터(whc.unesco.org), NASA, 국제기구·정부 기관 누리집, 미술관·박물관 공식 누리집.
   **쓰지 않을 출처: 위키백과, 나무위키, 블로그, 커뮤니티 글, 언론 기사 요약.**

## 4. 문항 작성

`CLAUDE.md`의 규칙 10개를 그대로 지킨다. 특히:

- 정답은 유일하다. 오답 3개는 그럴듯하되 출처 기준으로 명백히 틀리다(규칙 1, 7).
- 연도만 한 자리 바꾼 식의 허수 보기는 쓰지 않는다(규칙 7).
- 보기 4개는 서로 다르고, 길이와 형식(단위, 조사, 표기)이 비슷하다(규칙 3, 8).
- 최상급 표현(`가장`, `최초`, `최대` 등)을 쓰면 기준과 시점을 문제 문장에 넣는다(규칙 2). 예: `2024년 유엔 통계 기준, 면적이 가장 넓은 나라는?`
- 부정문으로 쓰지 않는다(규칙 9). `모두 맞음`, `위의 어느 것도 아님` 같은 보기를 쓰지 않는다(규칙 10).
- 출처 문장을 옮겨 쓴 뒤 문제 문장이 한국어 문법에 맞고 자연스럽게 읽히는지 다시 읽는다(규칙 5).

형식은 `PRD.md` 4.1과 4.2를 따른다.

```js
  {
    id: "kh-11",
    category: "한국사",
    question: "문제 문장",
    choices: ["정답", "오답1", "오답2", "오답3"],
    answer: 0,
    explanation: "60자 이내 한 줄 해설",
    source: { name: "기관·문서 이름", url: "https://사실이 적힌 페이지 주소" }
  },
```

- 작성할 때 정답은 **항상 `choices`의 0번**이고 `answer: 0`이다. 화면에서 섞인다.
- `explanation`은 60자 이내 한 줄이다.
- `source`에는 3단계에서 연 2곳 중 근거가 더 분명한 **1곳**을 적는다. 나머지 1곳은 아래 검수표에만 적는다.

## 5. 먼저 보여 주고 승인받기

**파일을 고치지 않은 채로** 만든 문항을 전부 보여 준다.

1. 카테고리 순서(한국사 → 세계지리 → 과학 → 예술과 문화)로 문항 전문을 위 `js` 형식 그대로 낸다.
2. 이어서 검수표를 낸다.

   | id | 정답 | 출처 A에서 확인한 내용 | 출처 B에서 확인한 내용 | 두 출처 일치 | 정답 하나뿐 | 최상급 기준·시점 |
   |---|---|---|---|---|---|---|

   - 출처 A는 `source`에 적은 곳이다. 두 칸 모두 기관 이름과 확인한 내용을 한 줄로 적는다.
   - 최상급 표현이 없는 문항은 마지막 칸에 `해당 없음`을 적는다.
3. "승인하시면 `questions.js`에 넣겠습니다. 문제가 있는 문항은 id로 알려 주세요"라고 적고 **멈춘다.**

### 일부만 승인한 경우

- 승인된 문항은 그대로 보류해 두고, **거절된 문항만** 새 주제로 3~4단계를 다시 돌려 5단계로 보여 준다.
- `4 × n`개가 전부 승인될 때까지 반복한다. **그 전에는 파일을 고치지 않는다.**
- 이렇게 해야 카테고리마다 문항 수가 같게 유지된다.

## 6. `questions.js`에 반영

전부 승인된 뒤에 한꺼번에 넣는다.

- 각 문항을 **자기 카테고리 블록의 끝**에 넣는다. 즉 다음 `// ----- 카테고리 -----` 주석 바로 앞이고, 예술과 문화는 배열을 닫는 `];` 바로 앞이다. 지금의 카테고리 묶음 순서를 깨지 않는다.
- 들여쓰기는 공백 2칸, 각 객체 뒤에 쉼표를 붙여 기존 문항과 형식을 맞춘다.

## 7. 검증

두 명령을 돌려 출력을 그대로 보고한다.

```bash
node -e "const fs=require('fs'),vm=require('vm');const c=vm.createContext({console,location:{search:'?test'}});for(const f of ['questions.js','script.js'])vm.runInContext(fs.readFileSync(f,'utf8'),c,{filename:f});process.exitCode=c.selfTestFailed?1:0"
```

기대: 마지막 줄이 `실패 0`이고 종료 코드가 0이다. 통과 개수는 프로젝트가 자라면 달라지므로 특정 숫자를 기대하지 않는다. (카테고리별 문항 수가 같은지는 `validateQuestions`가 검사한다.)

```bash
node -e "const fs=require('fs'),vm=require('vm');const c=vm.createContext({});vm.runInContext(fs.readFileSync('questions.js','utf8')+';globalThis.Q=QUESTIONS;',c);for(const q of c.Q){if([...q.explanation].length>60)console.log('해설 60자 초과',q.id,[...q.explanation].length);if(/가장|최초|최대|최소|최고|최장|최다/.test(q.question))console.log('최상급 확인',q.id,q.question)}"
```

기대: `해설 60자 초과`가 없다. `최상급 확인`으로 나온 문항은 문제 문장에 기준과 시점이 있다.

실패하면 고치고 두 명령을 다시 돌린다. 통과하지 못한 채로 끝냈다고 보고하지 않는다.

## 8. 보고

- 더한 문항 수와 id 목록(카테고리별)
- 카테고리별 문항 수가 지금 몇 개로 같아졌는지
- 7단계 두 명령의 출력
- 3단계에서 버린 주제가 있으면 무엇을 왜 버렸는지
- **커밋은 하지 않는다.** `questions.js`를 고친 것까지만 하고, 커밋과 브랜치 정리는 사용자에게 맡긴다.
